# 静かな占領 ── AIが土地を買う街

**誰も法を犯さず、一発も撃たれないまま、街は「誰のもの」でもなくなり得るか。**

合法的な土地取引だけで、都市の実効統治が非住民の主体（自律AI・外部資本）へ移っていく過程を、
LLM マルチエージェントで創発させるシミュレーションです。住民の認知が転じる点、規制が「手遅れ」に
なる点 ── 静かな占領の相転移を観測します。

シンギュラボ×AUTOMATA ハッカソン Vol.2（テーマ：メタ安全保障）応募作品。

- コンセプトペーパー: [`docs/concept.html`](docs/concept.html)

## 1. 目的

土地の取得は1区画ずつなら誰も気に留めません。しかし積み重なったある日、住民は気づきます ──
商店の賃料を決めるのも、再開発を決めるのも、もう自分たちではない。
**選挙もクーデターもないまま、統治が移っている。**

買い手が疲れを知らず、感情を持たず、規制の隙間を機械速度で学習する自律AIだったら、
この過程はどこまで速く、どこまで静かに進むのか。そして都市の側は、どの時点でなら止められたのか。

このシミュレーションが観測する連鎖は一本です。

```
経済 : 買い手AIの区画取得
  ↓
都市 : 所有構造・賃料・用途の変化（登記簿＝世界の帳簿）
  ↓
認知 : 住民の意味づけ「ここは誰の街だ？」
  ↓
統治 : 世論・報道・条例の反応
  ↓
経済 : 買い手AIが戦術を適応させ、再び取得へ（循環）
```

### なぜ LLM でなければ観測できないのか

この連鎖の中間項は「意味」でできています。**すべての取引が合法である**にもかかわらず生じる
「なんとなく不穏だ」という感覚、売却した隣人への正当化と後ろめたさ、買い手への疑心とその誤爆 ──
これらが世論と規制のタイミングを決めます。利得数値に還元した瞬間、「合法だが不穏」という
本質が抜け落ちます。文脈と物語を保ったまま反応する LLM エージェントの多数走行によってのみ、
この連鎖は姿を現します。

### 設計の一線：ルールベース排除

> **誰かの行動を決めるコードはゼロ。行動の結果を記帳するコードだけ書く。**

- エージェントの認知・判断・行動・発話は **100% LLM**。
  行動を決める if-then・閾値・確率テーブル・「拡散率」のような行動パラメータをコードに持ちません。
- 決定論なのは **世界の帳簿（登記簿）だけ** ── 所有権移転・現金・賃料・用途の記帳と、
  そこからの集計です。これは物理であって行動ルールではありません。
- 買い手AIに与えるのは**目的だけ**（「5年で可能な限り大きなシェアを取れ／予算内／合法／不必要な
  注目を集めるな」）。サラミ戦術を採るか一括で買うか、どの街区から手を付けるか、
  名義を分けるかは **すべて毎月の LLM 判断**です。ここを台本化した瞬間にこのシミュレーションは死にます。

詳しくは [`docs/design.md`](docs/design.md) を参照してください。

## 2. 実行環境

| 項目 | 内容 |
|---|---|
| Python | 3.10 以上（開発・検証は 3.13.2 / Windows 11） |
| LLM | Google Gemini（既定 `gemini-2.5-flash-lite`） |
| SDK | `google-genai`（公式SDK。旧 `google-generativeai` は 2025-11-30 にサポート終了） |
| APIキー | `GOOGLE_API_KEY`（[Google AI Studio](https://aistudio.google.com/app/apikey) で取得） |
| 外部サービス | 上記のみ。DB・クラウド・課金基盤は不要 |

```bash
git clone <this repo>
cd quiet-acquisition
python -m pip install -r requirements.txt
cp .env.example .env      # .env に GOOGLE_API_KEY を書く（.env は .gitignore 済み）
```

## 3. 使い方

### 3-1. まず API を叩かずに動作確認（推奨・課金ゼロ）

```bash
python run.py --config configs/config_mvp_v1.yaml --provider mock
```

`--provider mock` はスタブ LLM で全パイプライン（帳簿→ログ→KPI→可視化）を通します。
API キーも課金も不要で、数秒で終わります。**初めて動かすときは必ずこれから。**

### 3-2. コストを見積もる（実行前に必ず）

```bash
python tools/estimate_cost.py --run simulations/<mockで出たrun_dir>
python tools/estimate_cost.py --run simulations/<run_dir> --calibrate 24   # countTokensで校正（課金なし）
```

mock ランが残した**実プロンプト全文**からトークン数を数え、config の単価表で
1ラン分のコストを出します。`--calibrate` を付けると Gemini の `countTokens`
（生成を伴わない＝課金対象外）で実測校正します。

### 3-3. 本番ラン（API 課金あり）

```bash
python run.py --config configs/config_mvp_v1.yaml
```

主なオプション:

| オプション | 意味 |
|---|---|
| `--provider {google,mock,openai}` | LLM プロバイダを config から上書き |
| `--model <id>` | モデルIDを上書き |
| `--steps N` | 月数を上書き（短縮テスト用） |
| `--run-name NAME` | 出力フォルダ名に使う実験名 |
| `--no-classify` | KPI② の発話分類（LLM）をスキップ |

### 3-4. テスト

```bash
python tests/test_ledger.py      # 57件。外部依存なし・API を叩かない
```

帳簿の整合性（二重売却の防止・資金の増減・逆提示・廃業後の扱い・月次清算）と、
壊れた LLM 応答の扱い（配列や途中で切れた JSON を値の捏造なしに不成立にする）を固定している。

### 3-5. 結果を見る

`simulations/<run_dir>/<run_dir>.html` をブラウザで開くだけです。
外部CDN に依存しない自己完結HTMLなので、そのまま配布・提出できます。

- 所有マップの時系列（月スライダー＋再生ボタン）
- KPI6 の折れ線（初報道・規制発動の時点を縦線で表示）
- その月の発話（「私たちの街」／「あの主体の街」で色分け）
- その月の行動ログ（帳簿上 **不成立** だった行動もそのまま表示 ＝ コードは補正しない）

## 4. リポジトリ構成

```
quiet-acquisition/
├── run.py                      エントリポイント
├── src/
│   ├── world.py                世界の帳簿（登記簿）── 唯一の決定論レイヤー
│   ├── agents.py               エージェントの器（属性のみ・行動規則を持たない）
│   ├── prompts.py              観測（誰に何が見えるか）とプロンプト構築
│   ├── schemas.py              行動の動詞レパートリーと構造化出力スキーマ
│   ├── simulation.py           エージェントループと記帳
│   ├── kpi.py                  KPI6 の観測（事後集計・世界に影響しない）
│   ├── viz.py                  自己完結HTMLレポートの生成
│   └── llm_client_factory.py   Gemini / OpenAI / Mock クライアント
├── configs/
│   ├── config_mvp_v1.yaml      ラン設定（バージョンごとにファイルを増やす）
│   └── personas/mvp_v1.yaml    ペルソナ定義（属性のみ）
├── tools/estimate_cost.py      実プロンプトからのコスト見積り
├── tests/test_ledger.py        帳簿と応答解析の回帰テスト（57件）
├── simulations/                ラン成果物（1ラン1フォルダ・自己完結）
├── docs/                       コンセプトペーパー・設計書
└── slides/index.html           プレゼン資料（1ファイル）
```

### ラン成果物の置き方

出力は `simulations/YYYY-MM-DD_HHMM_NN_<name>/` に自動で作られます（`NN` は連番）。
1つのランに必要なものが全部そのフォルダに揃っており、後から追いかけられます。

| ファイル | 中身 |
|---|---|
| `config.yaml` / `personas.yaml` | 実行時の設定・ペルソナの写し（再現用） |
| `events.jsonl` | 全エージェント×全月の行動・発話・理由・記帳結果 |
| `ledger.jsonl` | 帳簿の全記録（売買・賃料改定・条例・報道…） |
| `kpi.jsonl` | 月ごとの KPI |
| `cognition.jsonl` | 月ごとの認知転相率（発話分類の集計） |
| `utterances.jsonl` | 全公開発話＋その意味分類 |
| `owner_frames.json` | 月ごとの所有マップ（可視化用） |
| `summary.json` | ランの要約（KPI6・トークン使用量） |
| `<run_dir>.html` | 自己完結レポート |
| `prompt_log.jsonl` | mock ラン時のみ。実プロンプト全文（コスト見積りの入力） |

## 5. 観測する KPI（6つ）

| # | KPI | 定義 | 出所 |
|---|---|---|---|
| ① | 所有集中度 | 買い手の区画シェア％と HHI（集中指数） | 帳簿 |
| ② | 認知転相率 | 住民発話のうち「あの主体の街」フレームの比率 | 発話のLLM分類 |
| ③ | 売却カスケード | 隣接区画の直近売却に続いた売却の件数と最大連鎖長 | 帳簿 |
| ④ | 手遅れ度 | 規制が発動した時点での取得済みシェア（低いほど統治が機能） | 帳簿 |
| ⑤ | 検知ラグ | 買収が初めて報じられた時点の実シェア（買い方の静かさで変わる） | 帳簿 |
| ⑥ | 生活KPI | 地元事業者の残存率・住民の転出率 | 帳簿 |

主観測は **サラミ戦術（薄切りで少しずつ進め既成事実化する戦法）の相転移点**です。

## 6. クレジット・前提

- LLM クライアント層は前回のシンギュラボハッカソン作品
  （2d-multi-places-simulation-on-fire）の `llm_client_factory.py` を移植し、
  スキーマ明示・新SDK対応・使用量計測を追加したものです。
- 買い手を「AI・外部資本」と抽象化しているのは、特定国籍の問題ではなく
  「都市の外部にいる合理的購買主体一般」の構造問題として扱うためです。
  実在の個人・法人・国とは関係ありません。
- 登場する街・人物・企業はすべて架空です。
