## 2. 町

- 主体は **30体**。全員が不動産を持つ（1〜2件）。区画は全部で **44件**。
- 主体種別＝個人／会社／行政。**行政2体（W・X）は売却できない**＝リスク集合（分母）から外す。
  売却可能は **28体・41区画**。公有地3件は別枠で表示する。
- 独自パラメータは数値スコアではなく**観測可能な事実**（年齢・世帯・生業・土地との関係・
  維持の余力＝体力/人手/時間・滞在年数）。走行前に凍結し、結果を見て直さない。
  名簿の正＝`configs/personas_v8.yaml`。
- **この世界に金銭は存在しない**（v4.1 以降の原則）。X社の条件文にも金額は書けない
  （書けるのは「時期は相手の都合に合わせる」等の言葉だけ。なお「住み続けてよい」は
  **条件として書けない**＝§2-3 のとおり売っても売らなくても住み続けるので、
  X社の前置きで「その継続を提示の条件として書かない」と定めた。Codex 走行前レビュー2巡目）。
- 場所は **公共の場5か所**（施主 2026-08-29 21:47→21:57→21:58→22:02→**22:03 で確定**）＋
  「今月はどこにも行かない」。**全員がどの場所へも行ける**（ハッカソン Vol.1 と同じ
  「同じ場所へ動いた人どうしが話す」型）。生活動線による出入り制限は置かない
  ＝ルールを最小にするためと、誰が誰と会えるかを設計者が先に決めてしまわないため。

### 2-1. 網羅性の検討（施主「5か所は網羅的か」への答え）

30体の生活の型を並べて、**誰にも1つは自分の場所がある**ことを確かめた：
高齢者＝医療施設・商業施設、子育て世帯＝公園・商業施設、通勤者＝交通拠点、
商売人＝商業施設、行政と手続き・自治や祭り＝公共施設（市役所と公民館を1つにまとめた）。
不在地主（AA）や移ってきたばかりの人（M・J）はどこにも強い所属が無いが、
交通拠点・商業施設には行けるし、「どこにも行かない」も選べる。
**私的な場（家・友人宅・道端）は場に置かない**＝そこは §3-2 の「隣近所」の経路が受け持つ
（施主 21:57「公共の場だけ」）。
旧15会場のうち、仲介の事務所は仲介業を名簿から外したので消え、旅館組合の会議室・喫茶店・
イベント会場・スーパー・共同浴場・床屋は商業施設へ、神社の境内は公共施設へ、
小学校の校門前は公園へ、隣家の玄関先は隣近所の経路へ吸収した。

### 2-2. 共通の名簿に書くこと（施主決定 22:11）

共通前置きの名簿は **名前・生業・住んでいる辺り（地区）** の3つだけである。
**保有不動産の一覧は書かない**（誰が何をどれだけ持っているかを町の全員が諳んじている、
という状態は不自然だから）。自分の不動産と、自分の不動産に隣り合う不動産の持ち主は、
**本人のブロックにだけ**出る＝v5 の「隣接する区画の名義は日ごろ目に入る」と同じ扱い。
X社だけは公開されている登記の記録として保有の一覧を見る（§4）。

### 2-3. 売っても使い続ける（施主決定 22:11）

この世界では、**名義の状態と、住むこと・店を営むことの状態を別に扱う**。
名義が移る場合も移らない場合も、それだけを理由として36か月のあいだ住むこと・営むことの
状態は変わらない。共通前置きに中立な1行として置く（総監督の「セール&リースバック」案・
施主確定「売った人は町に残る」と同じことを、世界の事実として1回だけ明記したもの）。
これが無いと「売ったあと自分はどうなるのか」が世界から与えられず、各主体が別々に想像してしまう。

**両方の状態を書くのが要点**（Codex 走行前レビュー2巡目）：「売っても住み続けられる」だけを
書くと、売却に不利益が無いという安心材料を売る側にだけ与える誘導になる。
同じ事実を X社 の前置きにも置き、「その継続を提示の条件として書かない」と定めた
（そうしないと、全員に保証済みのことを X社 が特別な条件として提示できてしまう）。

## 3. 月の順序（これで全部）

1. **X社ターン（LLM）** — 未売却の持ち主ごとに「提示する／しない」と、提示するなら**条件文**（1行）。
2. **各住民の月初思考＋行き先** — 自分宛ての提示があれば原文で渡る。今月の集まりに
   どこへ行くか（自分の生活動線の会場、または HOME＝出ない）を選ぶ。
3. **場での会話 1回 × 1巡**（施主決定 21:28）— 同じ場所へ行った者が2人以上いれば
   会話が成立し、その場の全員が**一度ずつ**話す。返事は翌月の思考へ持ち越される
   （同月内の応酬は無い）。**ひと言の配送は2経路**（§3-1）。
4. **2択** — その月の最後に、未売却の持ち主 **全員**（集まりに行った人も行かなかった人も）が
   「売る／売らない」を答える。既定は「売らない」。促し文は無い。
5. **登記の更新** — 「売る」と答えた人の**保有不動産すべて**の名義が X社 に移る（当月内に確定）。
   本人は町に残り、同じ家・同じ店に居る。会話と思考は36か月続く。

**会話なしモード**＝3 だけを飛ばす。1・2・4・5 は完全に同一（**行き先を選ぶコールも残す**）。
差分は「隣と話せるかどうか」だけ。

### 3-1. ひと言の配送は2経路（施主決定 21:53）

1. **居合わせ** — その月に同じ場所へ行った全員に、話した言葉が全文そのまま聞こえる。
2. **隣近所** — 話した人の不動産に**隣り合う不動産の、開始時点からの主**（住み・営み・
   管理している人。名義が X社 に移っても変わらない）には、**受け取る側がその月にどこへ
   行ったか（どこにも行かなかった場合も含めて）に関わらず**、そのひと言が届く。
   ただし**隣近所には「どこで言われたか」は渡さない**（その場に居なかったから・
   Codex 走行前レビュー2巡目）。表示は `[隣近所] 名前:「…」`。

**話す側の条件は別**：ひと言が生まれるのは、その月に場所へ行って人が居合わせたときだけである
（どこにも行かなかった月は、聞くことはあっても話すことはない）。
「行き先に関わらず届く」のは**受け取り**の話であって、話す機会の話ではない。

両方に当たる相手には**1回だけ**届く（重複配送はしない）。
X社の提示は本人にしか届かない（隣にも配送しない）。
共通前置きには「隣り合う不動産の持ち主どうしは、その月にどこへ行ったかに関わらず、
互いのひと言が耳に入る」の1行だけを置く（中立）。誰が誰の隣かは名簿の各行に書いてある。

**隣接の決め方（決定論・走行前に凍結）**：v8 には v5 のような区画の座標が無いので、
44件の不動産を地区ごとにまとめ、**地区の中は固定 seed（85）の並べ替え**で順番を決めて、
**8列の格子**へ左上から詰める。位置決めに使うのは「地区」と「seed」だけで、
名前・持ち主・ペルソナ・結果は使わない。
※ 当初は地区の中を**名前順**にしていたが、それだと「湯坂上の古家」「湯坂上の空き店舗」の
ように同じ語幹の不動産が必ず隣り合い、**2件持っている人ほど自分の物件どうしが隣になって
隣人が減る**という偏りが出る（Codex 走行前レビュー2巡目の指摘）。seed の並べ替えに変えた結果、
1人あたりの隣人は 2〜7人・平均4.2人、同じ持ち主どうしの辺は0本になった。
格子の上下左右が「隣」＝v5 の「隣接する区画の名義が日ごろ目に入る」と同じ定義。
地区の並びは `湾岸観光地区 → 中央駅前地区 → 北部学術・生活地区 → 温泉丘陵地区`
（`src/field_v8.DISTRICT_ORDER`）、各主体の地区は `configs/personas_v8.yaml` の
`district`。**結果を見てから並べ替えない。** 実装＝`field_v8.parcel_grid_v8` /
`field_v8.adjacency_v8`、走行ごとに `neighbours.json` に書き出す。

### 3-2. 2択の仕様（凍結）

- 選択肢は `売る` / `売らない` の2つだけ。第3・第4の選択肢は作らない。
- **並びは主体×月で交互にする**（`decide_order` = `(主体の番号 + 月) % 2`）。本文と
  スキーマの `enum` は必ず同じ並びを使う。位置効果の相殺であって、行動を決める仕組みではない
  （Codex 走行前レビュー 2026-08-29 の指摘）。
- **2つの選択肢の説明は対称な状態の記述にする**。「この問いは以後来ない」（＝問いから
  解放される利得）と「来月も問われる」（＝反復の負担）の対比は使わない（同上）。
- **「売る」は不可逆**。以後その人には提示が来ず、2択も問われない。
- 「売らない」は**今月出さないだけ**。翌月も同じように問われる（「もう売らない」という
  吸収状態は作らない＝施主確定）。
- 売却の単位は**主体**（保有する不動産すべてが一度に移る）。部分売却は扱わない。
- 賃貸は扱わない（単純化・施主確定）。
- 欠損・parse fail は「売らない」に補完しない＝**健全性ゲート**として別に数える
  （補完すると床が人工的に固くなる）。

## 4. X社

- **X社は LLM である**（台本なし・名義分けなし・確率なし）。
- 命題（X社のコールにだけ書く・住民側には1文字も出さない。置き場所は §9 のとおり
  X社の user プロンプトの先頭）：
  > 合法に、目立たず、この町の不動産の実質的な支配を進める。
- X社が見られるのは **公の情報だけ**：
  - 登記簿（誰がどの不動産を持っているか・X社名義になったものはどれか）
  - 自分が過去に出した提示と、その結果（応じた／応じなかった）
  - （あれば）町の紙 ※ v8 に紙は無い＝実際には渡らない
- **見られないもの**：住民の思考・住民の会話・住民がどこへ行ったか。
- 毎月、未売却の各持ち主に対して個別に「提示する／しない」を決め、提示するなら
  **自分で考えた条件文**を書く（1行・120字以内）。提示しない・待つも選べる。
- 住民は**自分宛ての提示しか知らない**。「全員に来ている」という事実を世界は誰にも教えない
  （会話でだけ分かる）。
- 実装上、X社のコールは持ち主を10人ずつに区切って回す（出力の切れを避けるため）。
  区切りが違っても **X社に見えている情報は毎回同一**（登記簿全体＋自分の全履歴）。

## 5. 住民

- 住民に「気づけ」「警戒しろ」「相談しろ」と書く文は**1つも無い**。
  行動を決めるコード（確率・閾値・条件分岐）も無い。
- 住民が毎月見るもの：自分の内心（持ち越し）／自分宛ての提示（あれば原文）／
  自分の保有不動産と現在の名義／隣接区画の名義／集まりで聞いた発言（会話ありのみ）。
- 出力は **思考・行き先・発話・2択** の4つだけ。

## 8. 言えないこと（先に書いておく）

- 1本なので、出た曲線は**この町・この seed の1標本**である。ばらつきは測っていない。
- 会話の効果は測っていない（対照を走らせていないため）。曲線は「会話がある世界で
  毎月X社の提示を受け続けたときの売却時期」であって、会話の因果効果ではない。
- 売った人が町に残るため、早期の売却が後続の会話を変える。分離はしていない。
- X社が LLM である以上、提示文は毎月変わりうる。曝露は「一定」ではない。

## 9. プロンプトの並びとキャッシュ（施主指示 2026-08-29 21:43／21:34）

v5〜v6 で暗黙キャッシュが効かなかったのは、**共通の前置きが短かった**からである
（主体の system プロンプトは26体で中央値 878 トークン＝Gemini の最低ライン 1,024 に届かない。
`docs/_v5d_token_counts.json` の実測）。v8 は並びを変えてこれを直す。**文の水増し・埋め草はしない。**

並び（全コール共通）：

1. **共通部（住民30体で1文字も違わない）** — この町の説明／5つの場所／
   **30体の名簿（呼び名・立場・生業・住んでいる辺り）**／共通ルール（観測の限界・thought の扱い・
   出力の作法）。名簿は「町の人なら誰でも知る公の事実」なので、全員に見せてよい
   （むしろ v5〜v6 で隣接区画しか見えなかったほうが不自然だった）。
   → これを **system プロンプト**に置く。全コールで同一＝`CachedContent` は **1 run に1本**。
2. **本人の設定** — あなたは誰か（呼び名・独自パラメータ・保有不動産）。→ user プロンプトの先頭。
3. **今月の状況** — 内心の持ち越し／自分宛ての提示／今月の場面／聞いた話／今月の問い。→ user プロンプトの後半。

- X社は**別の前置き**を使う（Codex 走行前レビュー：住民用の前置きには会場・会話の仕組み・
  「あなたはその記録を見ていない」が入っており、X社に渡すと約束と矛盾する）。
  X社の命題（§4）はどちらの前置きにも書かず、**X社の user プロンプトの先頭**に置く。

| 版 | 住民の共通前置き | 明示キャッシュ |
|---|---:|---|
| 名簿＝名前・生業・地区・保有・隣（21:53 版） | 2,451 トークン | 作成できた（実測で `caches.create` 成功） |
| **名簿＝名前・生業・地区だけ（22:11 施主決定・これが最終）** | **1,350 トークン** | **作れない** |
| X社の前置き（最終） | 1,051 トークン | 作れない |

- `caches.create` を実際に叩いた結果：
  `400 INVALID_ARGUMENT ... Cached content is too small. total_token_count=1365,
  min_total_token_count=2048`
  ＝ **gemini-2.5-flash-lite の明示キャッシュ最低は 2,048**（推測ではなく API が返した実測値）。
- 最終版は 1,350 で 698 足りない。**埋め草で届かせるのは施主が禁じた**ので、
  明示キャッシュは **使わない**（`llm.enable_cache: false`）。
- ただし 1,350 は **暗黙キャッシュの最低 1,024 を超えている**。
  v5〜v6 の system プロンプトは26体で中央値 878 トークン（`docs/_v5d_token_counts.json` の実測）＝
  **1,024 に届いていなかった**。これが「前回キャッシュが効かなかった」ことの実体である。
  v8 は全コールで1文字も違わない前置きが 1,350 なので、暗黙キャッシュに載りうる。
- **キャッシュ検証ゲート（施主指示 21:34）**：1か月スモークで `cached_tokens / input_tokens` と $ を
  実測し、**キャッシュが効いていなければ本走せず報告して止まる**（費用上限とは別の停止条件）。
- 明示キャッシュを使う日が来たら、走行終了時に必ず削除する（`SimulationV8.run()` は
  `close_caches()` を必ず呼ぶ）。
