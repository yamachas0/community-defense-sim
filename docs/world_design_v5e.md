# A市フィールド v5e — 赤の再定義／自衛レベル／自衛が出たら台本停止／目玉第15月／36か月

設計の正はこのファイル。施主GO 2026-08-28 23:53。v1〜v5d の設定・成果物は**一切変更しない**
（v5e は新しい設定・新しい観測ファイル・新しい run として足す）。

## 0. 絶対ルール（この便でも変わらない）

- **狙った動きを出す仕組みを作らない。** 住民（主体）への入力＝プロンプト・観測・兆候・
  同席・巡数・記憶の渡し方は v5d と**1バイトも変えない**。兆候は増やさない・減らさない。
- 変えてよいのは3つだけ：
  1. **観測側**（赤の定義・自衛レベルの副分類・気づきの連鎖の抽出）＝事後の読み方であり、
     主体には一切見せない。
  2. **買い手の台本**（目玉物件の月・自衛が出たら取得を止める＝買い手側の反応）。
  3. **月数**（24 → 36）。
- 分類の閾値・語彙を「結果を見てから」動かさない。定義は走行前に凍結する。
- 停止の判定に使ってよいのは**観測側と同じ分類器の出力だけ**。別の仕掛け・別の閾値を作らない。

## 1. 赤の再定義（施主 2026-08-28 23:43）

> 行政が動いた、の定義についてはおかしそう。ここでは静かな占領が進んでいることに対する
> 具体的なアクションが起きたかどうかを観測する…活用だとか面的な開発やまちづくりだとかって
> いう話題ではまだそこに至っていない。

**赤＝「複数の土地が同じ相手に渡っている」という事態そのものに対して、具体的なアクションが
起きた行。** 主体の立場（行政かどうか）は問わない＝v5c の「行政の発話に限る」制限を外す。

**赤にしないもの**（誤検知の主因として明示する）:
- 空き地の活用・まちづくり・面的な開発・地域の活性化といった一般論
- 個別案件の窓口相談・問い合わせ
- 「関係部署と連携して検討する」「実態を把握したい」型の、対象もやることも定まっていない定型応答
- 記者の取材依頼と、それに答えただけの発言
- 心配・不安・噂の共有・感想だけの発言

判定は v5c と同じ二重（`stage = ルール1次抽出 ∧ LLM ラベル`）。青・緑・黄の定義と語彙は
**v5c から1文字も変えない**（比較のため）。変わるのは赤だけ。

### 1-1. LLM 側（`STAGE_SYSTEM_V5E`）

`deal` / `area` / `same_buyer` は v5c の文言をそのまま使う。`admin` を捨て、`defense` と
`defense_level` を足す。文言は `src/kpi.py` の定数を正とする。

### 1-2. ルール側（`src/stage_v5e.py`）

```
rule_red_v5e(text, holders, acquired)
  = （S1語 ∪ S2語 ∪ S3語 のいずれかを含む） かつ （_v5c_rule_blue が真）
```

- **役割の制限は付けない**（v5c の「行政の発話に限る」を外す＝S1 は住民の行だから）。
- **`rule_blue` を要求する**のが要点（Codexレビュー 2026-08-28 指摘①）。自衛語だけを見ると
  「説明会をやる」「条例で対応する」といった、買い手の話とまったく無関係な行政・地域の一般論が
  そのまま赤になる。赤は青の上位＝**その行が土地取引・名義・持ち主のいずれかに触れていること**を
  1次抽出の必要条件にする（青緑黄と同じ登り方に揃える）。
- 否定形（「規制はしない」）・仮定形はルール（単純な部分一致）では落とせない。**LLM の `defense`
  が「取った・取ると決めた・呼びかけている」を要求する**ことで落とす＝二重判定の役割分担。
  誤検知が残る可能性は監査で全件目視して報告する。
- 語彙は下の §2 に列挙したものを**走行前に凍結**する。v5c の `V5C_ADMIN_WORDS` は使わない。

## 3. 自衛が出たら台本の取得を停止（買い手側の反応）

> こういう動きが出たら、台本の売買は停止としよう。（施主 23:53）

- 各月の**終わり**に、その月の発話・内心・記事を**観測側と同じ分類器**（`classify_stage_v5e`）で
  分類する。ルール側も同じ `src/stage_v5e.py` の関数を使う（コードを二重に持たない）。
- その月に**赤（＝S1〜S3 のいずれか）が1行でも成立**したら、`stop_month = その月` を立て、
  **翌月以降の台本の取得を全て停止**する。
  - 既に成立した契約（賃借を含む）は不変。取得済みの土地はそのまま。
  - 停止後も会話・内心・記事・兆候の配布は最終月まで続く（買い終わり後の観測と同じ）。
  - 停止は主体に一切知らされない（プロンプトに出ない・観測にも入らない）。
  - **起きなかった取得の兆候は配らない**（CTO 判断 2026-08-29）。兆候は「その取得が現実に
    生む痕跡」なので、取得が成立しない以上その痕跡も存在しない。残すと**起きていない売買の
    証拠**を住民が見せられる＝世界が住民に嘘をつく。落とすのは**停止月以降の分だけ**で、
    停止前に既に配られた準備の痕跡（測量など）はそのまま残す（その時点では買い手は
    現実に動いていた＝取りやめになった準備として筋が通る）。
- 停止した月・トリガー行（原文全文・主体・役割・場・レベル）を `defense_stop_v5e.json` と
  `summary.json` と `deals_v5.jsonl`（`kind: "script_stopped"` の行）に記録する。
- **月次分類の結果をそのまま最終の `stage_labels_v5e.jsonl` として使う**（事後にもう一度
  分類し直さない＝同じ入力に二重課金しない・判定が二本に割れない）。
- 誤検知で止まる可能性は監査で報告する（停止トリガー行は人手で全件目視）。

## 4. 目玉物件＝第15月

一等地イベント（`ACQ18` / `P04` / 中心・表通り・店舗・140㎡・目立ちやすさ7）を
**第12月 → 第15月**へ移す。

**根拠**＝施主の指示「目玉は15か月目くらいにしよう。これ行政含めて自衛がどう言うレベルで働くかも
みたいね」（2026-08-28 23:53）。観測したいのは**自衛が働くかどうか**であり、そのためには
目立つ1件が起きた**後**に街が反応する時間が要る。36か月の走行で目玉を中盤（15/36）に置くのは、
①その前に静かな取得が積み上がる期間 ②その後に反応が現れうる期間 の**両方を確保する**という
台本（買い手側）の設計判断である。

> **明記**：これは「結果を見てから当てにいく調整」ではない。v5c の結果（24か月で黄が1人）を
> 根拠に月を選んだのではなく、**36か月という尺の中盤に置く**という位置づけで決めている。
> 走行後にこの月を動かすことは禁止する（動かせば台本を結果に合わせて調整したことになる）。

**他の取得（順番・区画・名義・kind・note・兆候）は seed85 のまま1バイトも変えない。**
実装は台本の再生成ではなく `tools/build_events_v5e.py` による**その1行の移動**
（traces を持つ場合は同じ差分だけずらす。P04 の traces は v5d で0本）。
第15月には既に `ACQ22`（P19）があるので、第15月は2件になる。第12月は `ACQ19`（P05）の1件になる。

## 6. 「気づきの連鎖」（観測のみ・機械抽出）

`present.html` のパネル。本ごとに、緑／黄／赤（S1〜S3）の**各初出**について、その行の直前に
本人が受け取った入力を鎖で見せる：

1. 同席者の発話（`deliveries` の `kind:"scene"`・その月・その場・その行より前）
2. その月に本人へ配られた兆候（`traces_v5.jsonl`）
3. その月に本人へ届いた記事（`kind:"article"`）
4. その月に本人へ届いた私信（`kind:"direct"`）
5. 本人の過去の内心（`thoughts_all.jsonl` のうち、その行より前で直近のもの）

**既存の JSON にある行だけを引く。新しい語彙・新しい判定・新しい兆候は足さない。**
数値・引用は JSON 由来のみ。既存の `ignition`（strict）を拡張する形で
`tools/build_present_data.py` に `awareness_chain` として出す。

## 8. 初出の並び順（Codexレビュー 2026-08-28 指摘④）

v5c の集計は同じ (月・シーン・ラウンド) の中を `kind` の**文字列順**で並べていた
（`article` < `thought` < `utterance`）。実際には1回のコールで「内心 → 発話 → 記事」が同時に
生まれるので、記事が先頭に来るのは誤りである。v5e の集計では

```
KIND_RANK_V5E = {"thought": 0, "utterance": 1, "article": 2}
並び順 = (月, シーンの順, ラウンド, KIND_RANK_V5E[kind], 主体ID)
```

とする。同じラウンドの**別主体どうし**は並列に呼ばれていて真の前後関係が存在しないので、
主体IDで決定論に並べる（前後があると読ませない）。**v5c の集計の並び順は変えない**
（既存の成果物が動かないように）。

## 9. この便の限界（正直に書く・報告にもそのまま載せる）

Codex の設計レビュー（2026-08-28）が挙げた点のうち、**施主の指示で意図的にそうしている**もの。
隠さずに限界として記録する。

1. **停止は「観測が世界に戻る」経路である。** v5c/v5d の分類器は走行後に1回動くだけで世界に
   戻らなかった。v5e では月次の分類結果が買い手の台本を止める＝**分類器の出力が世界の状態を
   変える**。これは施主が明示的に指示した「買い手側の反応」であり、住民への直接の入力
   （プロンプト・兆候・同席）は変えていない。ただし**停止した月以降の v5e は、v5c/v5d や
   「停止しなかった場合」と直接は比較できない**。停止後の街の様子は「取得が止まった世界」の
   観測であって、「自衛の効果」の証明ではない。
2. **36か月化はプロンプトを変える。** `src/field_v5.py:570,605` が `=== 第{step}月 / 全{n_steps}月 ===`
   を出しているので、`steps: 24 → 36` は主体が読む文字列を変える。純粋な観測側の変更ではない。
   月数は施主指示なので実施するが、**v5d（24か月）との差分は「月数」と「目玉の月」と「停止」の
   3つが混ざったもの**であり、どれか1つの効果を分離して主張してはならない。
3. **赤の定義を変えた以上、v5c の赤と v5e の赤は別物である。** だから v5c 3本を新しい定義で
   **再分類**して、`RESULTS.md` に旧赤／新赤を並記する（§5）。
4. **停止の誤検知は残りうる。** ルールは部分一致・LLM は1行だけを見る。停止トリガー行は
   全件を人手で目視し、誤検知だったものは「誤検知だが止まった」と明記する（止め直さない）。
