# v5d 世界修正 — 役場の窓口を廃止／土地と持ち主の呼び名を統一／台本の兆候を戦略に合わせて絞る

設計の正本。**走行前に固定する**。施主FB 2026-08-28 20:41 / 20:49 / 21:06。

## 0. 絶対ルール（この便で一番大事なこと）

施主 21:06 までのFBには「基本はばれずに終わる → あるとき誰かが気づく → 伝搬 → 報道で一気に」という
**望ましい筋書き**が書かれている。**これを仕組んではならない**（施主自身が「↑これを仕込もうとはしないでね」と明記）。
この便で触ってよいのは **世界が住民に渡している入力の非現実** だけである。

- 足してよい：無し（気づかせる経路・観測者・機構は1本も足さない）
- 消してよい：現実には起きないこと（窓口で登記を見に行く日常／買い手の戦略に無い工事）
- 直してよい：呼び名（P番号・R番号は人間の街の言葉ではない）

v5c までの設定・台本・成果物（`mvp_v1` 〜 `field_v5c`）は1文字も変更しない。v5d は別ファイルで足す。

## 1. 土地の名前と持ち主の呼び名（B-1）

対応表は `configs/parcel_names_v5c.yaml`（v5d でも同じ表を使う＝画面とシミュで呼び名が食い違わない）。

### 1-1. 土地の名前

`<locality>の<use_word>`。48区画すべてに固有名を付け、`name` も `locality` も全区画で重複しない。

- `locality` ＝ 区画の位置（地区・通り・海／丘／川・角地かどうか）から、街の人が呼ぶときの言い方を当てたもの。
- `use_word` ＝ `parcels_v5c.yaml` の `use_detail` から機械対応（公共施設→集会所／旅館→旅館／店舗→店／
  事業所→事業所／住宅→家／古い住宅→古家／空地→空き地）。
- **面積・用途・位置などの世界の事実は変えない。** 変えたのは呼び名だけ。

### 1-2. 持ち主の呼び名

`<本拠の locality>の大家さん`（施主の言葉「A を持っている人は A の大家さん」をそのまま採る）。

- **本拠** ＝ ①店子がいる区画（＝実際に貸している）を優先 → ②無ければ pid 最小の区画。
  16世帯の本拠 locality は互いに重複しない。
- 1世帯が2〜3区画を持つ（48区画÷16世帯）ので、**土地と持ち主が1対1にはならない**。
  本拠だけが呼び名の由来になり、残りの区画は「浜町の大家さんが持っている桜台の古家」と呼ばれる。
  これは現実の街の呼び方と同じであり、**新しい手がかりを足していない**
  （v5c でも隣接区画の名義と登記の名義は同じ範囲で見えていた）。
- **施主の言葉からの逸脱（CTO判断・要事後承認）**：施主は「A を持っている人は A の大家さん」と言ったが、
  日本語の「大家」は**貸主**を指す。貸していない12世帯に「大家さん」と呼びかけると、
  住民LLMに「この人は誰かに貸している／複数を貸している」という**世界に存在しない事実**を推論させる
  （Codex レビュー 2026-08-28 が同じ指摘）。賃貸関係そのものが観測対象なので、歪めてはならない。
  → **本拠に店子がいる4世帯（HH01/02/03/05）だけ「◯◯の大家さん」、残り12世帯は「◯◯の持ち主さん」**。
  施主が「全部 大家さんでいい」と言うなら `parcel_names_v5c.yaml` の `agents[].name` を書き換えるだけで戻る。
- 事業者（店子）＝「<借りている区画の name>さん」（例：浜町の旅館さん）。
- 仲介・行政・記者は土地を持たないので役割から呼ぶ（二代目の仲介さん／駅前の仲介さん／
  市役所のまちづくり担当さん／市役所の観光産業担当さん／地域紙の記者さん／地域ウェブの記者さん）。
- 法人名義（X社・A社〜D社）は**変更しない**。土地名に記号 A/B/C を使っていないので衝突しない。
- 公有地の登記名義は「A市」と表示する（人の名前ではないため）。

### 1-3. 内部IDへの降格

`P01` / `R01` / `HH01` / `V01` は**内部ID**とし、**プロンプト・登記・台本の note・記事・私信・分類器の語彙・
画面の本文には出さない**。出てよいのは JSON のキー・ログ・デバッグ表示だけ。
tests で「原文に P番号・R番号が出ない」を固定する。

集計側（`tools/run_metrics.py` の `V5_PARCEL_RE` 等）は、**この表から機械生成した名前の正規表現**に差し替える。
語彙を人手で足すのではなく、**1対1の対応表から作る**（新しい語彙を発明しない）。

## 2. 役場の窓口の廃止（B-2）

施主 20:41「普通わざわざ窓口行って登記確認しないし、周りが聞いているシチュエーションじゃない。
役場の待合はまだわかるけど。」

- `S4_ROTATION` から `counter`（市役所の窓口）を削除する。v5d の S4 は
  **町内会（V02）／仲介の店先（V07）／記者の取材（V08）の3か月周期**。
- `registry_rows_v5`（窓口で閲覧できる登記の全件）を v5d では**一度も呼ばない**。
  `[窓口で閲覧した登記の記録]` のブロックはプロンプトに出ない。
- **`市役所の待合`（V06）は会場として残す**（S1〜S3 の行き先として選べる）。そこでは登記は見えない。
- 台本の `audience: "registry"` の兆候（seed85 で33本）は**配送先が無くなる**ので、
  v5d の台本から取り除く。これは「兆候を減らした」のではなく、**見に行く場所が無くなった**結果である。
- プロンプトの世界知識の文言を、機構と矛盾しないように直す：
  - 旧：「土地登記は公開情報である。ただし記録を見に行かなければ内容は分からない。」
  - 新：「土地の名義は公式に記録されている。ただしあなたはその記録を見ていない。
    名義が変わったことは、当事者から聞くか、目に見える様子から察するほかない。」
- 行政ロールの追記文（「市役所の窓口が開く月には、窓口で人の話を聞く」）を
  「市役所の待合で人の話を聞くことがある。特別な権限や制度はこの街には無い。」に直す。
- **登記が街に届く経路は既存の3本だけ**：①売主・貸主本人が当事者として話す ②目に見える兆候
  ③仲介が仕事の中で知る（`broker_known`）。**新しい経路は1本も足さない。**
  記者には登記を引く経路が無い（v5c でも窓口へ行く以外の手段は無かった）。

### 見立て（結果がどう変わるか）

v5c の着火点は**登記を見られる場所（市役所・仲介）**だった。窓口を廃止すると、
第2弾で判明した「登記を見た記憶」からの着火が消える。青（個別の売買の話）は当事者と近隣から、
緑（面としての話）は兆候と噂の重なりからしか立ち上がらなくなる。
**気づかれずに終わる本が増える方向に振れると予想するが、それは結果であって目的ではない。**
予想が外れても台本・機構を触らない。

## 3. 台本の兆候を「買い手の戦略が現実に生む痕跡」に絞る（B-4 / 施主 21:06）

X社の戦略＝**土地の実質支配が目的・当面は解体も新築もしない**（`docs/world_design_v5c_buyer_strategy.md`）。
この戦略のもとで**現実に痕跡が出るか**を種類ごとに判定する。**判定は根拠で行い、件数の目標を置かない。**

実装は `tools/build_events_v5d.py`＝`configs/events_v5c_seed85.yaml` を読み、
**取得の順番・月・区画・名義・note を1バイトも変えずに、traces だけを下の表で濾す**。
（RNG を回し直さないので、取得の不変が構造的に保証される。）

| 種類 | seed85 の件数 | v5d の判定 | 根拠 |
|---|---|---|---|
| `registry`（窓口で見える名義変更） | 33 (sale 33) | **全削除** | 窓口を廃止したので配送先が無い（§2）。街の誰も見に行かない。 |
| `construction`（工事・足場） | 9 (sale 8 / lease 1) | **全削除** | 買い手は当面 解体も新築もしない。工事は起きない。 |
| `sign_change`（看板が替わった） | 13 (sale 6 / lease 7) | **売買は全削除／賃借かつ店舗のみ残す**（文言を「見慣れない名前の看板が掛かった」に直す） | 名義が移っただけで看板は替わらない。賃借は買い手が使い手になる取引なので、空いていた店に名前が出るのは現実。 |
| `tenant_swap`（使い手が替わった） | 8 (lease 8) | **賃借のみ残す**（現状どおり。文言を「使う人が変わった」に直す） | v5b の修正で賃借の対象は使い手が居ない区画に限られる＝「入れ替わった」ではなく「使い始めた」。 |
| `moving_out`（住人・店が引き払った） | 7 (sale 5 / lease 2) | **売買かつ「売主本人が使っていた区画」のみ残す** | 自宅・自店を売れば引っ越す。空地・不在地主・貸家（店子継続）では起きない。賃借では所有者は変わらない。 |
| `survey`（測量している人がいる） | 9 (sale 8 / lease 1) | **売買のみ残す** | 日本の土地売買では引渡し前の境界確定測量が一般的。賃借では通常やらない。 |
| `strangers`（見慣れない人が見て回る） | 7 (sale 6 / lease 1) | **売買のみ残す** | 買う前の現地確認・仲介の案内は現実に起きる。賃借は既に決まった相手が使うだけ。 |
| `broker_known`（仲介が仕事の中で知る） | 7 (sale 5 / lease 2) | **全部残す** | 仲介は職業上、名義の移転を知る。売買・賃借どちらでも成立する。 |

**バイアスの自己点検**：この表は6種類のうち2種類を全削除し、3種類を条件付きに絞る＝
**痕跡が減る方向にだけ働く**。減らす根拠は「買い手の戦略に無い行為は起きない」であり、
**街が気づきにくくなることを狙ったものではない**。増やす方向の追加は1件も入れていない
（増やす根拠のある種類が無かったため）。この非対称は Codex レビューの明示的な確認対象とする。

## 4. 節約設定を既定に（B-3）

`configs/config_field_v5d.yaml` は `docs/cost_saving_v1.md` の結論をそのまま既定にする。
