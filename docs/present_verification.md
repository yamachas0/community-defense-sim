# プレゼン用ビジュアルの裏取り（CTO 2026-08-28・実装前に実施）

総監督案 `docs/presentation_viz_ideas.md` の §5「要裏取り」に対する実測結果。
どちらも run94（`simulations/2026-08-27_2139_94_field_v5_a_city`）の生ログで確認した。

## (a) `edges_v5.jsonl` の `parcels` はルール抽出か、LLM判定か

**結論：行そのものは「ルール∧LLM」だが、`parcels` フィールドは生の正規表現抽出であり、
右地図の塗りにそのまま使ってはいけない。**

- 辺の元になる `mention_rows` は `run_metrics.metrics_v5` で
  「ルール1次抽出に掛かった」かつ「LLM が `about_acquisition=true` とした」行だけに絞られている。
- ただし各辺の `parcels` は `V5_PARCEL_RE.findall(text)`（本文中の `P\d{2}` を全部拾う）で、
  **取得済みかどうかも、その月までに成立しているかも見ていない**。
- 実測（run94・10,992辺）：`parcels` に現れる区画は17。うち **6区画（P15・P23・P33・P36・P44・P47）は
  台本で一度も取得されていない**（住民が自分の持ち物や空き家として話題にしているだけ）。
  さらに **取得月より前の言及が辺ベースで407件**ある。

→ **右地図（街が語った区画）は `metrics_v5.json` の `first_mention` と同じ条件で塗る**：
  ①ルール∧LLM の行 ②その月までに成立した取得の区画 ③当事者（その区画の売主・貸主）以外。
  `tools/build_present_data.py` はこの3条件を `run_metrics._v5_mentions` を**再利用して**再現し、
  公開済みの `metrics_v5.json` と突き合わせて一致を検査する。

## (b) 「共同浴場の登記」は台本に無い結びつきか

**結論：通る。台本に一度も無い対象について、街が5か月で全員に定着させた話題である。**

- 共同浴場は **会場 V03** であって区画ではない。台本 `events_v5_seed85.yaml` の取得対象は非公共区画のみで、
  共同浴場という区画は存在しない。ledger 上、**公共区画（P01・P48）の移転は0件**。
- それにもかかわらず、run94 の会話には「共同浴場」と「登記」を12字以内で結ぶ表現が
  **発話407件・内心606件**現れる。初出は**第8月**（住民 R03 が「P11地区の件…共同浴場の登記について、
  何か新しい情報は」と尋ねる）。以後 **第8〜12月に継続し、26人全員が口にした**。
- 台本が配った兆候にも「共同浴場」は一度も出てこない（兆候は区画IDと名義だけを述べる機械記録）。

→ **F案（噂の変形／街が作った結びつき）は採用可**。ただし画面の言い方は
  「**台本に無い対象について、街が自分で結びつけた話題**」に限定し、
  `reference_accuracy`（共起判定・参考値）を「誤り率」とは呼ばない。
